Dieses Dokument hält wichtige Designentscheidungen für unsere App fest – vor allem, wie einzelne Module und Komponenten aufgebaut sind. Ziel ist, die technische Struktur übersichtlich darzustellen und den späteren Code leichter nachvollziehbar zu machen.

== Schnittstellen

Unsere App verwendet eine REST-API, um Frontend und Backend zu verbinden. Darüber laufen z. B. Login, WG-Verwaltung, Artikelsuche und das Bearbeiten von Einkaufslisten. Die API ist nach dem OpenAPI-3.0.4-Standard beschrieben und mit Javalin in Java umgesetzt.

=== Auswahl zentraler Endpunkte

Die Tabelle unten zeigt eine Auswahl der wichtigsten Schnittstellen. Die komplette Beschreibung steht in der Datei `rest.yaml`.

|===
| Methode | Pfad | Beschreibung

| POST  | /user/create               | Nutzer registrieren
| POST  | /user/login               | Login mit Session-Cookie
| GET   | /user                     | Daten des eingeloggten Nutzers
| POST  | /wg/create                | Neue WG erstellen
| GET   | /wg/{wid}                 | WG-Daten anzeigen
| POST  | /wg/{wid}/user            | Nutzer zur WG hinzufügen
| GET   | /wg/{wid}/list            | Alle Listen in einer WG abrufen
| POST  | /wg/{wid}/list            | Neue Liste anlegen
| GET   | /wg/{wid}/list/{lid}      | Liste anzeigen
| POST  | /wg/{wid}/list/{lid}      | Artikel zur Liste hinzufügen o. ä.
| GET   | /wg/{wid}/item            | Artikel suchen oder filtern
| POST  | /wg/{wid}/item            | Neuen Artikel erstellen
| PATCH | /wg/{wid}/item/{iid}      | Artikel bearbeiten
| DELETE| /wg/{wid}/item/{iid}      | Artikel löschen
| POST  | /wg/{wid}/category        | Neue Kategorie anlegen
|===

Fast alle Endpunkte benötigen eine gültige Session. Fehler wie „nicht eingeloggt“ oder „kein Zugriff“ werden mit den entsprechenden Statuscodes (`401`, `403`) zurückgegeben. Daten werden als JSON gesendet und empfangen, verarbeitet wird das mit der Bibliothek `gson`.

== Technischer Aufbau

Unsere Endpunkte sind mit Javalin umgesetzt. Jeder Bereich (z.B. Listen, Items) hat eine eigene Klasse, in der alle zugehörigen Routen registriert werden z.B. `ListEndpoints.java` oder `ItemEndpoints.java`. Die API prüft bei jeder Anfrage, ob der Nutzer eingeloggt ist und zur jeweiligen WG gehört.

Für Anfragen nutzen wir eigene Request-Objekte wie `CreateItemRequest`. JSON wird mit `gson` (de)serialisiert. Felder ohne `@Expose`-Annotation werden dabei ignoriert.

Ein typischer Ablauf für `POST /wg/{wid}/item` sieht so aus:

- Nutzer wird authentifiziert
- WG-Zugehörigkeit wird geprüft
- Request wird validiert
- Neues Item wird erstellt und als JSON zurückgegeben
